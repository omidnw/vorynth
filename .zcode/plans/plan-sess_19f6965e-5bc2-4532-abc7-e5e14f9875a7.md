## Plan: Fix LLM mode, add user-controlled mode toggle & provider selection

### Root Cause of the Bug
`LlmService.isAvailable()` at `apps/core-engine/src/modules/llm/llm.service.ts:71` calls `provider.verify()` — a **live API call** to the provider. If this call fails (transient network issue, rate limit, etc.), the mode falls to "news" even though the user has a valid stored key. The user has a Gemini key but it shows "news mode" because verify() failed.

### Solution Overview
1. **Decouple** `isAvailable()` from live `verify()` — a configured provider (key decrypts OK) is considered available
2. **Add persisted mode setting** (`"engine.mode"` in `app_settings`: `"intelligence" | "news"`) so the user explicitly chooses
3. **Add active provider selection** (`"engine.activeProviderId"` in `app_settings`) so the user picks which provider to use
4. **Rename "LLM" → "Mode"** in the UI and add a toggle

### The fix in one sentence
The bug is that `isAvailable()` calls a live API `verify()`. We remove that call from availability detection — if the key decrypts, the provider is available. Then we add an explicit user-controlled mode toggle so the user decides "Intelligence" vs "News", not the network.
