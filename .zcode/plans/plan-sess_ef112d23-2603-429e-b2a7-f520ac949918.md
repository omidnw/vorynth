## Implementation Plan: Regenerate AI Details + Title Translation

Based on your answers (two separate buttons, naming up to me), here's the plan.

---

### Feature 1: Regenerate All Insights (Primary)

**What it does:** Regenerates the AI triad (`significance` / "Why It Matters", `impact` / "Impact", `recommendedAction` / "Recommended Action") for **all existing insights** using the user's selected AI Output Language from Profile.

**How it works:** Reads every row from `ai_insights`, looks up the corresponding article, calls `llm.analyze()` with the article content and target language, then **updates the insight in-place** (doesn't create duplicates).

**Backend changes:**

| File | Change |
|------|--------|
| `packages/types/src/index.ts` | Add `"regenerate"` to `JobKind` union type |
| `apps/core-engine/src/modules/intelligence/intelligence.service.ts` | New method `regenerateAllInsights(targetLanguage?)` — queries all insights with joined articles, iterates with rate-limited `llm.analyze()`, updates each insight row via raw SQL, reports progress via callback. Skips insights whose articles are missing. |
| `apps/core-engine/src/modules/jobs/jobs.controller.ts` | New `POST /jobs/regenerate-insights` endpoint — wraps `regenerateAllInsights()` in a background job of kind `"regenerate"`, counts total insights for progress, updates fraction on each iteration |

**Frontend changes:**

| File | Change |
|------|--------|
| `apps/desktop/src/features/jobs/jobs-api.ts` | New `startRegenerateInsightsJob()` → POST `/jobs/regenerate-insights` |
| `apps/desktop/src/features/jobs/jobs-store.ts` | New `startRegenerateInsights` action calling the API + refresh |
| `apps/desktop/src/pages/SettingsPage.tsx` | New GhostCard **below** the Re-collect card with title "Regenerate All Insights" and a secondary button, disabled when a `"regenerate"` job is active, with a `confirm()` dialog |
| `apps/desktop/src/i18n/en.ts` | New keys: `settings.regenerateInsights`, `settings.regenerateInsightsHint`, etc. |

**Button name:** **"Regenerate All Insights"** — aligns with the codebase's `Insight` type naming.

---

### Feature 2: Translate Story Titles (Secondary)

**What it does:** Translates all article titles to the user's selected AI Output Language while preserving the original.

**Schema change:** Add `original_title TEXT` column to the `articles` table via additive DDL (safe for re-runs).

**How it works:** For every article that has content but no `original_title`, the LLM translates the title and stores: `title` → translated, `original_title` → original. Articles already translated are skipped.

**Frontend display:** In the Brief view, title shown is the translated (`title`) or original if no translation exists. An "Original" badge/chip appears next to the title when `original_title` is set, togglable via a UI mechanism (e.g., clicking it swaps display).

**Backend changes:**

| File | Change |
|------|--------|
| `apps/core-engine/src/db/schema.ts` | Add `originalTitle` column to `articles` table in Drizzle schema |
| `apps/core-engine/src/db/ddl.ts` | Add ALTER TABLE `articles ADD COLUMN original_title TEXT` to `ADDITIVE_DDLS` array |
| `packages/types/src/index.ts` | Add `originalTitle?: string` to `Article` interface |
| `apps/core-engine/src/modules/intelligence/intelligence.service.ts` | New method `translateAllTitles(targetLanguage?)` — queries articles without `original_title`, calls LLM to translate each title, updates DB |
| `apps/core-engine/src/modules/jobs/jobs.controller.ts` | New `POST /jobs/translate-titles` endpoint (kind `"regenerate"` or new kind) |

**Frontend changes:**

| File | Change |
|------|--------|

| `apps/desktop/src/features/jobs/jobs-store.ts` | New store action |

| `apps/desktop/src/i18n/en.ts` | New translation keys |
| `apps/desktop/src/pages/BriefPage.tsx` | Display original vs translated title toggle |
